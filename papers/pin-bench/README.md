# CLBG experiment for the paper on `pin` (#8)

Seven programs of the Computer Language Benchmarks Game, the ones that
Câmara (2024) used for dyn-lex: binary-trees, fannkuch-redux, fasta, fib,
mandelbrot, n-body, spectral-norm. Each one exists in three versions
with the same algorithm and the same output:

- `c/`: plain C, single thread, `gcc -O2`; the floor;
- `lua/`: Lua, runs unchanged on Lua 5.4 and on LuaJIT (Lua 5.1 dialect:
  no `//` and no `<<`); the same language model, interpreted, and with a
  JIT, both with a tracing collector;
- `atm/`: Atmos, built three times, with `ATMOS_PIN=off` (counting only,
  `pin` only for tasks and pools), `ATMOS_PIN=unchecked` (the semantics of
  `pin`, no checks), and the default (the whole mechanism).

The programs were written for this experiment, from the algorithms of the
CLBG, and not taken from `alochaus/dyn-lex-benchmark`: its `.c` files
are C generated by the dyn-lex compiler, not reference C programs, and
its Lua files have debugging output and wrappers. Differences from the
CLBG: mandelbrot prints a checksum of the bytes instead of the image;
fasta uses the simple algorithm (one character at a time); binary-trees
in C uses `malloc` and `free` with no pool.

The outputs agree across all versions (checked at small sizes:
binary-trees 10, fannkuch 7, fasta 1000 by md5, fib 30, mandelbrot 200,
n-body 1000, spectral-norm 100).

## How to run

```
make -C ../..                          # the Atmos compiler and runtime
for f in c/*.c; do gcc -O2 -o ${f%.c} $f -lm; done
mkdir -p bin
for m in on unchecked off; do for p in binarytrees fannkuch fasta fib mandelbrot nbody spectralnorm; do
    ATMOS_PIN=$m ATMOS_CFLAGS=-O2 ../../atmos -o bin/$p-$m atm/$p.atm
done; done
gcc -O2 -o runm runm.c
./run.sh > results.csv                 # REPS=5 by default
python3 -I summary.py results.csv
```

Each program is compiled once, and only the run is timed: the flaw that
the author found in the earlier study (recompilation inside the timed
runs) does not apply. `runm` times one run (wall clock, monotonic) and
reports the peak resident memory of the child (`wait4`). The output of
the programs goes to `/dev/null`. The variants of a program alternate
within each repetition, so that a slow period of the machine affects
all of them.

`env.txt` records the machine and the versions.
