# atmos-cli: the command line of the language

Material for the session `atmos-cli`, where the author discusses the
command line of Atmos: the program `atmos`, its options, how it is
configured, built, installed, and told which environment to use.
Gathered on 2026-11-20 by the session that maintains the compiler
(`atmos-lang`). It has the request (section 1), what exists today (2),
what the sessions ran into (3), and questions with alternatives (4).
Nothing in section 4 is decided, and the author has not said yet what
he wants to change: section 3 is what was observed, not a list of
defects he accepted.

## 1. The request

**Autor** (2026-11-20, in `atmos-lang`):
> quero falar sobre a cli da linguagem. abra uma sessao `atmos-cli`

## 2. What exists today

The command line is `src/main.c` (about 300 lines); the manual
describes it in "Execution". On `main` at `deff4fa`.

```
Usage: atmos [-c] [-o <out>] [-t] [-e <env>] <input> [<args>] ...

   -c          Emit C only (to the standard output).
   -o <out>    Build only.
   -t          Enable test blocks.
   -e <env>    Include the file of an environment first.
```

| What | How it is today |
|---|---|
| Run | `atmos f.atm [args]`: compiles to C in memory, writes `/tmp/atmos-XXXXXX/main.c`, calls the C compiler, runs the executable with the arguments, removes both. The exit status is the program's |
| Build | `atmos -o out f.atm` keeps the executable and does not run it |
| C only | `atmos -c f.atm` prints the C to the standard output |
| Tests | `atmos -t f.atm` enables the `test` blocks of the program and of what it includes |
| Environment | `atmos -e env.atm f.atm` includes one file before the program. A dedicated compiler (`make env OUT=atmos-pico ENV=pico.atm ENV_CFLAGS=... ENV_LDFLAGS=...`) is the same program built with those as defaults: `atmos-pico`, `atmos-sdl`, `atmos-uv`, `atmos-iup` |
| Hidden options | `--lex` and `--ast` print the tokens and the tree; they are not in the usage |
| Order | Options come before the input; everything after the input goes to the program. An unknown option prints the usage |
| Configuration | Eight variables of the environment: `ATMOS_HOME` (where `rt/` and `build/` are), `ATMOS_CC`, `ATMOS_CFLAGS` (default `-O1`), `ATMOS_LDFLAGS`, `ATMOS_ASAN`, `ATMOS_REAL`, `ATMOS_INT`, `ATMOS_TIME` |
| The C build | `cc $CFLAGS <env flags> -w -I<home>/rt main.c <home>/build/libatmos[...].a -lm $LDFLAGS`. `-w` silences the warnings of the C compiler. A failure prints the errors of the C compiler and `atmos : C compilation failed` |
| The runtime | `make` builds `libatmos.a` and `libatmos-asan.a`; another numeric configuration is built on first use by `make -C <home>`, which needs `make`, the sources and a writable `<home>/build` |
| Install | None. The compiler is used from its checkout; a checkout may be moved after it is built |
| One input | One file; other files come by `include` in the program |

Not there: `--help` and `--version`, a way to keep or name the
generated C, a cache of builds (every run compiles the C again), a
project file, reading the program from the standard input, a REPL.

## 3. What the sessions ran into

- **Every port wraps the compiler in a script.** `run.sh` in
  `sdl-pingus` and `sdl-flare`, `tst/run.sh` in most, a `Makefile` in
  the environments: they find the checkout of the compiler
  (`ATMOS=../lang/atmos`, with a list of former names), set
  `ATMOS_CFLAGS` and `ATMOS_LDFLAGS` (`-lSDL2 -lSDL2_image ...`), and
  call it. `doom` notes: "the build needs `ATMOS=<checkout of
  ia-atmos/lang>`; to revisit if the compiler gets an installed form".
- **One compiler per environment.** `atmos-envs#4` (the selection of an
  environment, `make env` against `-e`) is open, and its `#11` too (a
  dedicated compiler forces its environment as the primary one). With
  two environments in one program (`atmos.env`, the pilot of uv with
  iup) the second is included by hand.
- **Compile time dominates short runs.** The `test` block of Pingus
  takes about 20 s, almost all of it the C compiler on one file of the
  whole game; its suite compiles the game once per test.
- **The on-demand runtime** cannot be built by an installed, read-only
  compiler (`atmos-float#15`).
- **A board is another build.** `env-esp32` uses `-c` and then compiles
  the C and the runtime sources itself, with its own flags
  (`-DATM_REAL_FLOAT`, `-DA_STK_MAX=...`, `-DATM_NO_CLOCK`).
- **Tests.** `-t` enables every `test` block reached; there is no way
  to name one, to list them, or to run the tests of several files.
  `atmos-envs#3` is making the environments open no window under `-t`.
- **Warnings** of the compiler (a pin given away) go to the standard
  error with no switch: they cannot be turned into errors or silenced.
- **Errors in native code** are reported by the C compiler; the
  generated C carries `#line` directives for the native literals, so
  they point at the `.atm` file. An error in the rest of the generated
  C (a defect of the compiler) points at the temporary file, which is
  removed.

## 4. Questions and alternatives

- **The shape.** Flags as today, or subcommands (`atmos run`, `build`,
  `test`, `c`), with `atmos f.atm` kept as the short form of `run`.
- **Configuration.** The eight variables as they are; a flag for each
  (`--real=float`, `--cflags=...`), the variable as the default; or a
  project file beside the program that the compiler reads, so that a
  port needs no script.
- **Environments.** `-e` with a file, as today; `-e` with a name found
  on a path (`-e sdl`), repeatable for two environments; the flags of
  an environment declared by the environment itself (in its `.atm`),
  instead of at `make env`; and what becomes of the dedicated
  compilers.
- **Install.** A `make install` with a prefix (the compiler, `rt/`, the
  libraries), where the on-demand runtime is built (a cache of the
  user), and how a port finds the compiler.
- **A cache of builds.** Keep the executable keyed by the generated C
  and the flags, so that a second run starts at once.
- **The generated C.** An option to keep it in a named file, and
  whether `-w` stays.
- **Tests.** `atmos -t f.atm` as today; a name or a pattern to select
  `test` blocks; several inputs; the exit status and the output of a
  test run.
- **Small ones.** `--help`, `--version`, `--` to end the options,
  `--lex` and `--ast` in the usage, the program from the standard
  input.
- **Other targets.** A mode that emits what a board or another build
  system needs (the C and the list of runtime sources and defines), for
  `env-esp32`.

What the reference implementation (`atmos-lang/atmos`, in Lua) offers
on its command line was not read here.
