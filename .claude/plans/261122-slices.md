# atmos-slices: slices with no copy

Material for the session `atmos-slices`, where the author discusses
slices of vectors (and maybe strings) that do not copy. Gathered on
2026-11-22 by the session that maintains the compiler (`atmos-lang`).
It has the request (section 1), what exists today (2), how the ports
would use it (3), what a view meets in the runtime (4), and questions
(5). Nothing in section 5 is decided.

## 1. The request

**Autor** (2026-11-22, in `atmos-lang`):
> Não temos slices, né? Como poderia ser? Seria útil hoje?
> Primeiro explique o que é em uma frase curta

`atmos-lang` answered (its `#116`): a slice is a contiguous piece of a
vector, from index `i` to `j`, taken in one expression with no loop.
There is none for vectors; strings have `string.sub`. Three forms:

| Option | Form | Cost |
|---|---|---|
| `#116a` | `vector.sub(t, i [, j])`, a copy, the same indexes as `string.sub` | one library function, no syntax |
| `#116b` | a syntax of its own, such as `t@(i, j)`, after the ranges `(a, b)` of `loop` | the grammar; `t@(x)` is already indexing by an expression |
| `#116c` | a view with no copy, that refers into the original vector | meets `pin` (a reference into a pinned value must not outlive it) and aliasing (changing the original changes the view) |

It recommended `#116a`, with no hurry (four hand-written copies in the
ports).

**Autor** (2026-11-22, in `atmos-lang`):
> Crie sessão atmos-slices
> A ideia é não ter cópia

So the direction is `#116c`, a view; how it looks and behaves is for
this session.

## 2. What exists today

On `main` (2026-11-22).

- Vectors are the vector part of a table: `ATab.arr` with `an` elements
  from index 0 (`rt/atmos.h`, `struct ATab`: `arr`, `an`, `acap`, then
  the hash part `ents`, `en`, ...). `#t` is the length of the vector
  part. `t@i`, `set t@+ = v` (append), `vector.insert`, `remove`,
  `clear`, `sort`, `join`. `loop i, v in t` walks it.
- Strings: `struct AStr` holds its bytes inline (`char s[]`, with
  `len` and `hash`), immutable. `string.sub(s [, i [, j]])`: the
  substring from `i` to `j`, both included, default first and last; a
  new string. Used 63 times in the ports.
- No slice of a vector in the library, the manual or the branches.
  `atmos-iter` (branch `iter`) adds `iter.*` functions over iterables
  (find, filter, map, any, all, fold, sum, min, max, keys, values,
  zip), all eager, giving new vectors; its `#12`/`#13` discuss vector
  and dictionary as kinds of a table.
- `atmos-tag` (branch `tag-rebased`, merge approved 2026-11-22): the
  tag of a table moves to a field of its header, out of the keys.
- Memory (manual, "Lexical Memory Management"; `TODO-pin.md`): values
  are reference counted, the counts are part of the semantics; every
  value belongs to a block; a value may only be stored where its block
  lasts at least as long; `pin` fixes a value to its block; unpinned
  cycles leak.

## 3. How the ports would use it

Counted on 2026-11-22 over the clones of the ports, comments left out;
approximate.

Hand-written copies of a piece of a vector (a loop over a range that
appends):

| Port | Where | What |
|---|---|---|
| `pico-1oom` | `src/game/game_aux.atm:107` | `game_aux_tail(p, offs, len, from)`: `p@(offs+k)` for `k` in `(from, len-1)` |
| `pico-1oom` | `src/game/game_save.atm:962` | the rest of a save after its header: `bs@k` for `k` in `(HDR, #bs-1)` |
| `sdl-snxkx` | `src/save.atm:171` | the words of a line after the first |
| `env-ray` | `classics/space_invaders.atm:125` | append `g.all@i` for `i` in `(#g.enemies, n-1)` (a growing prefix) |

Other places that would take a view rather than a copy were not
searched: a function that walks part of a vector given by two indexes
(the ports pass `(t, i, j)` by hand), a buffer read in pieces (the
saves of `pico-1oom`, the bytes of a file), the tail of a list of
arguments.

## 4. What a view meets in the runtime

- **Representation.** A view is a new kind of value (a reference to a
  table plus `off` and `len`), or a table whose `arr` points into
  another's. The first keeps `ATab` as it is; the second makes every
  table operation ask whether it owns `arr`.
- **Life.** A view holds its base: by a reference count (the base
  lives while a view lives), or by the rule of blocks (a view of a
  pinned vector may not leave its block, like `set :out`). Under the
  rules of `pin`, a view is a reference into a value.
- **Changes of the base.** `set t@i` shows through the view (aliasing:
  the point of no copy). An append that grows `arr` moves it
  (`realloc`): a view by pointer dangles, a view by `(base, off)` does
  not. `vector.remove`/`insert`/`clear`/`sort` on the base move the
  elements under the view: whether the view follows the indexes or is
  invalidated, or whether a vector with views is frozen.
- **Writes through the view.** `set v@i = x` writes the base (as Go)
  or is an error (a read-only view). Append to a view (`set v@+`):
  error, or grows into the base (Go's surprise), or copies.
- **Strings.** Immutable, so a substring with no copy has no aliasing;
  but `AStr` keeps its bytes inline, so a view needs another kind of
  string (base, off, len), and the hash, the C API (which reads `A_STR_OF(v)->s`
  directly) and the interning of keys would see it.
- **What reads a view.** `#v`, `v@i`, `loop in v`, `iter.*`, `++`,
  `vector.join`, `X.dump`, `type(v)`, `??`, passing to C: which of them
  accept a view as a vector, and whether it is a table for `type`.
- **The tag** (after `atmos-tag`): a view of a tagged vector has the
  tag of the base, or none.
- **Cost.** A check of the kind of value in every vector operation, or
  none if a view is its own type that only some operations take.

## 5. Questions

- The form: a function (`vector.view(t, i, j)`), a syntax (`t@(i, j)`,
  `t[i..j]`), or both; inclusive bounds as `string.sub` and the ranges
  of `loop`, or half-open as Go and Python; negative indexes.
- A view is a vector to the program (same `type`, works everywhere a
  vector does), or its own type.
- Read-only or writable; what append to a view does.
- What a change of the length of the base does to its views.
- The life of a view under `pin` and the blocks.
- Strings too, or vectors only.
- A view of a view (one level, offsets added).
- Copy when needed: `vector.sub` (the `#116a` copy) beside the view, or
  a copy through `++ []` or `iter.map`.
- The reference (`atmos-lang/atmos`, in Lua) has no slices; Lua has
  `table.move` and `string.sub` (copies).
