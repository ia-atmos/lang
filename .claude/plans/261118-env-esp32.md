## What the repository is

`ia-atmos/env-esp32` is, today, a copy of `pgvalle-research/atmos-esp32`
at its `master` (`d56bcb0`, 2026-11-17): "Lua Atmos on ESP32", by Pedro
Valle (140 of 145 commits, since 2026-07-04; 5 by the author). It runs
the Lua implementation of Atmos on the board: a Lua 5.5 VM over ESP-IDF
v6, with the programs in a LittleFS partition as bytecode.

## How it relates to this implementation

- This implementation (`ia-atmos/lang`) compiles Atmos to C, with no
  Lua VM: a task is a record of 184 bytes plus its frame (72 per trail,
  16 per local), against a Lua coroutine of about 1 KB; no tracing
  collector (reference counting and the blocks of `pin`); the runtime
  uses `malloc`.
- Since 2026-11-17 (`81986e7`, `c12cf52`, `129eb6a`) an environment is
  registered in Atmos with `atmos.env([mode=..., step=..., quit=...])`,
  primary and secondary, the same shape as `lua/esp32/*.lua` here: the
  clock as primary and one secondary per binding would carry over
  almost as they are, with the C of the bindings called from native
  literals instead of through the Lua API.
- The generic `main` of the runtime (`rt/main.c`) is a loop that calls
  the steps; on the board it must run inside a FreeRTOS task and feed
  the watchdog, as `main/main.c` does with a Lua hook.

## Questions for the author, in the session

Nothing decided; one at a time, each with a recommendation after the
session reads the code.

- **The goal**: keep this repository as the Lua port (Pedro's work) and
  add the C backend beside it, replace it, or only study it? Who owns
  the repository from now on (Pedro's `pgvalle-research/atmos-esp32`
  goes on; this is a copy at one commit).
- **The first step**: the same `atm/init.atm` (PWM fade and IR) built by
  `ia-atmos/lang` into the ESP-IDF application, with the C bindings
  reused, and a comparison of what the two versions cost on the board
  (flash, free heap, events per second: `debug.Mem` and `debug.Fps`
  already print them in the Lua version).
- **What the compiler lacks for a board**: cross compilation (today
  `atmos` calls the host `cc` and runs the program; an option to only
  emit C exists, `-c`), a runtime with no `nanosleep`/`clock_gettime`
  (the clock of `rt/main.c`), the size of the runtime in flash, 32-bit
  targets (pointers and `AVal` sizes), reals as `float` (item 3 of the
  list of the compiler: 32-bit reals), `malloc` on a small heap.
- **Testing with no board**: nothing here can be flashed. The options
  are a host build with the bindings mocked (scripted events), Espressif's
  QEMU for the ESP32, and the author or Pedro with the hardware.
  Installing ESP-IDF or QEMU in the container needs the author's
  permission.
- **The Lua-specific parts**: `require`, the streams library
  (`f-streams`), `compile_lua.py`, the GC tuning: which have an
  equivalent, and which are not needed.
- **The submodules** point to `git@github.com:pgvalle-research/...`
  (SSH): they do not clone in a cloud session.
