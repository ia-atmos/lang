# atmos-grab: a block that captures an event

Material for the session `atmos-grab`, where the author discusses issue
22 of `atmos-lang/atmos` ("Grab primitive"). Gathered on 2026-11-18 by
the session that maintains the compiler (`ceu-atmos`), from the code of
the ports as it is today. Item 39 of the list of the compiler session.

## 1. The issue (text only: its one comment could not be read here)

```
grab :key.dn {
    watching :X {
        every :key.dn {
            ;; only this block reacts to :key.dn
        }
    }
} ;; release on :X
```

- other regions ignore the event pattern
- reentrancy? yes, a stack; or no, an error
- uses: modal dialogs that need exclusive keyboard input; focus
  management (only the focused component receives events); preventing
  event "leakage" to background tasks

## 2. What the language has: `toggle`

`toggle t(false)` silences a task (optionally `with :draw`, which still
passes), and `toggle on :E { ... }` a block driven by an event. Both
act from the OUTSIDE: who silences must hold the task, or be the
ancestor of the block. A modal is usually spawned deep INSIDE what it
must silence. Uses today: env-ray 27, pico 6, Pingus 5, env-sdl 4,
SNKRX 2.

## 3. Real cases

| Port | Where | What it does today | What `grab` would change |
|---|---|---|---|
| SNKRX | `src/options.atm` (`Pause`, `Options`, `PauseTime`) | Escape opens the options while the arena runs. The modal is spawned inside the arena, so it cannot `toggle` it: the game time is slowed to 0 (`eng.slow(st.v)`, tweened over 0.25 s) and keys still reach the game behind the modal | The clearest case: the options grab the keys and the mouse from inside, at any depth |
| SNKRX | `src/shop.atm:741`, `src/credits.atm:99` | The tutorial over the shop: `toggle on :Shop.on with :draw { await ShopMain(...) }`, driven by `emit @:task :Shop.on [false]` from a sibling branch | The tutorial grabs the input; the shop needs no toggle block nor the event that drives it |
| env-iup | `exs/7guis/circles.atm` (`adjust`) | The dialog that adjusts a diameter is modal: the branch that awaits it is deaf by sequence, but its siblings (undo, redo) stay alive. The program deactivates the main dialog in IUP (`iup.set(dlg, "ACTIVE", false)` / `true`) | The adjusting task grabs `:action` and `:value` while the canvas is still drawn: a grab needs a filter, as `toggle ... with` has |
| env-ray | `classics/classic.atm` and 5 classics (arkanoid, asteroids, asteroids survival, tetris, space invaders) | Pause: `toggle play(false) with :draw`, a `watching :key.dn [key='P']` that draws "GAME PAUSED", then `toggle play(true)`; the pause needs the reference `play` | A pause task that grabs the keys, with no reference to the game |
| Pingus | `main.atm` (`toggle on :screens`), `game/game.atm:249` (`toggle clock(false)`) | F5 or a menu button pause the screens and show the options over them; the game pause stops the clock | Options over the screens grab the input; the toggle of the clock stays (it is about time, not input) |
| env-sdl, env-pico | `exs/rocks/main.atm` | 'P' toggles the battle off and on (`toggle battle(false)`) | Same shape as env-ray |
| Flare | not yet | Inventory, vendor, and dialogs are next in the port (none written) | A grab would be designed in, not retrofitted |

## 4. Questions for the design

- What is grabbed: an event pattern (`:key.dn`), a set of them, or all
  but a filter (`with :draw`, as `toggle`)?
- Who still receives: the grabbing block only, or its block and its
  descendants? What about the tasks that the grabbing block spawns into
  a pool outside it?
- Reentrancy: options over the shop over the arena ask for a stack
  (the issue's "yes, stack"), not an error.
- Release: by the end of the block (lexical), as the issue shows.
- Cost in the runtime: a check per emit against the top of the stack of
  grabs; how it composes with `toggle`, `emit @t`, `atm_emit_to`, and
  with the order of awaking.
- The reference: `lua-atmos` and `atmos-lang/atmos` (does either have
  it?), and prior art (focus in GUI toolkits: Tk `grab`, X11 grabs,
  IUP modal dialogs, `SDL_SetRelativeMouseMode`).
