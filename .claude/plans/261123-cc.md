# atmos-cc: the time of a build with includes

Material for the session `atmos-cc`, where the author discusses the time
it takes to build a program made of several files. Gathered on
2026-11-23 by the session that maintains the compiler (`atmos-lang`).
It has the request (section 1), a first measurement (2), how a build
works today (3), and questions (4). Nothing in section 4 is decided.

## 2. A first measurement

`sdl-pingus`, `main.atm` with its 22 source files reached by
`include`, on `main` of 2026-11-23, one run each on this container:

| Phase | Time |
|---|---|
| Atmos to C (`atmos -c main.atm`: lexer, parser, includes, resolver, coder) | 0.42 s |
| C compile of the generated file, `cc -O0 -c` | 5.9 s |
| the same, `-O1` (the default of `ATMOS_CFLAGS`) | 20.7 s |
| the same, `-O2` (what `sdl-pingus/run.sh` sets) | 34.8 s |

The generated file has 91 thousand lines (3.0 MB), 583 functions, the
largest of 4479 lines (`atm_T0`, the main task) and 3072 lines
(`atm_T226`), and a `atm_consts_init` of 1234 lines.

So the time is almost all the C compiler on one large file, not the
translation, and it grows with the optimization level. `include` itself
is cheap: it pastes the statements of each file in place, once per file
(`src/parser.c`, `include_file`), and everything becomes one C unit.
Not measured yet: where `cc -O1` spends its time (one large function,
the constants, or the whole), and what part comes from each included
file.

## 3. How a build works today

`src/main.c` (manual, "Execution"; `261120-cli.md` for the whole
command line):

- `atmos f.atm` translates the program and every include into one C
  text, writes it to `/tmp/atmos-XXXXXX/main.c`, runs the C compiler
  once, runs the executable, removes both. `-o out` keeps the
  executable; `-c` prints the C.
- The C command: `$ATMOS_CC $ATMOS_CFLAGS <env flags> -w -I<home>/rt
  main.c <home>/build/libatmos[...].a -lm $ATMOS_LDFLAGS -o <exe>`.
  `ATMOS_CC` defaults to `cc`, `ATMOS_CFLAGS` to `-O1`. The runtime is a
  prebuilt library; only the program is compiled at each run.
- No cache: every run compiles the whole C again, even with no change.
- No option shows what is happening; a failure of the C compiler prints
  its errors and `atmos : C compilation failed`.
- C flags only through the variables `ATMOS_CFLAGS` and `ATMOS_LDFLAGS`
  (and `make env ... ENV_CFLAGS=... ENV_LDFLAGS=...` for a dedicated
  compiler); no command-line flag.
- Who suffers: the `test` block of Pingus took about 20 s, its suite
  compiles the game once per test; `doom`, `sdl-flare`, `sdl-tux` and
  the others wrap the compiler in scripts that set the flags.

## 4. Questions

- **Separate compilation (the author's 1).** Options, which may
  combine:
  - split the generated C into several units (one per included file,
    or per group of functions) and run the C compiler on them in
    parallel; the functions are `static` today and refer to each other
    and to globals, so they need declarations shared between units;
  - a cache of object files keyed by the C text of each unit and the
    flags, so that a file that did not change is not compiled again;
  - a cache of the whole executable, keyed by the C and the flags
    (the cheapest; helps only runs with no change, as a suite);
  - modules compiled apart with an interface (a real separate
    compilation, with what an include exports); the largest change,
    and it meets the resolution of names across files;
  - only lower the default optimization for runs (`-O0` while
    developing), as a measure apart.
- **`--verbose` (the author's 2).** Which phases to show (read and
  include of each file, resolve, generate C, C compile, link, run),
  with the time of each; on the standard error; whether it also prints
  the C command line; one level or several (`-v`, `-vv`).
- **C flags on the command line (the author's 3).** A spelling such as
  `--cc-flags=...`, `--cc-O2`, `--cc=clang`, or a general
  `--cc-<flag>` passed through; how they combine with `ATMOS_CFLAGS`
  and `ATMOS_LDFLAGS` (replace, or add); `--ld-...` for the link.
- **Relation with `atmos-cli`.** That session discusses the whole
  command line (subcommands, configuration, a cache of builds, the
  generated C, `--help`); `--verbose`, the `--cc-` flags and a cache
  overlap with it. Agree with it, or decide here and tell it.
- **Measure first.** Where the C compiler spends its time on the
  Pingus file (`-ftime-report`), and the same on `doom`, `sdl-snxkx`,
  `sdl-flare`.
