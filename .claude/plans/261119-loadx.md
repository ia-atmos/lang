# atmos-loadx: a loader of data that accepts names

Material for the session `atmos-loadx`, where the author discusses a
second loader of the library `X`, `loadx`, that reads data with
definitions of names and uses of them. Gathered on 2026-11-19 by the
session that maintains the compiler (`atmos-lang`), from a proposal of
the session `pico-slides`. It has the request (section 1), the proposal
(2), what exists today (3), and what is open (4). Nothing in sections 2
and 4 is decided: the idea is the author's, the details are the reading
of `pico-slides`.

**Outcome (2026-11-20).** Settled with the author in `atmos-loadx` and
on `main`: see `TODO-loadx.md` (items #1 to #23) and the manual, "Load
with Names". It departs from the proposal below: there is no spread
(the `...` of the sketch was an ellipsis), so `TITLE...` does not exist;
a name is used as a value only, each use a copy; the first definition
of a name wins; `include "file"` reads a file of definitions;
`X.loadx([dir,] s)` is a new function, and `X.load` did not change.

## 2. The proposal (from `pico-slides`)

`X.load` reads a value written with constructors only. `loadx` reads a
text with definitions of names before the value, and uses of those
names inside it:

```
TITLE = [ font=[size=0.08], color=[fg=:blue], anchor=:C ]
NOTE  = [ font=[size=0.03], color=[fg=:gray] ]

:Slides [
    :Slide [ title=:text ["Cultura", TITLE...],
        "Marrocos possui ...",
        :text ["fonte: Wikipedia", NOTE...],
    ],
]
```

The result is the same plain value that `X.load` gives for the expanded
text: the names disappear at load time.

Why it came up: in `pico-slides` a presentation is one tagged table, a
tree (`:Slides` > `:Slide` > blocks such as `:Row`, `:Col`, `:List`,
`:text`, `:image`), with style in groups that inherit down the tree
(`color=[fg=,bg=]`, `font=[file=,size=]`, `cell=[pad=,gap=]`). With
names in the data file:

- a style used many times (the title, a caption) is one name, with no
  table of themes in the engine;
- a block that repeats (a logo, a footer) is one name;
- the question "is the document only data or may it carry functions"
  gets a middle answer: names and reuse, no code.

An alternative with no change to `X`: the document as an Atmos program
with `val TITLE = [...]`. It works today, loses the guarantee of data
only, and still needs the spread.

## 3. What exists today

- `X.load(s)` and `X.dump(v)`: `rt/lload.c`, manual section "X"
  (`doc/manual.md`, around line 3570). The grammar of the loader, from
  the top of the file:

  ```
  Value : `nil´ | `true´ | `false´
        | [`-´] NUM | CLK | STR | TAG
        | [TAG] `[´ { Entry `,´ } `]´
  Entry : ID `=´ Value
        | `@´ Key `=´ Value
        | Value
  Key   : `(´ Value `)´ | NUM | STR | TAG
  ```

  It is data only: no variables, operations, functions or calls.
  Comments are accepted. `X.load(X.dump(v))` is structurally equal to
  `v`; a dump only writes data with no cycles.
- A bare `ID` as a value is an error in `X.load` today, so the text of
  section 2 does not load, and no text that loads today uses a name:
  `loadx` could also be `load` itself, extended, with no text changing
  its meaning.
- The language has no spread of a table. In a constructor, only the
  variadic `...` or a call as the LAST positional entry expands into
  several entries (manual, "Tables"). `X...` with named fields, in any
  position, does not exist.
- Who uses `X.load`: `sdl-pingus` (levels, sprites, worldmaps: all its
  data files), `sdl-tux`, the plans of Flare and of the media
  environment. Their files have no reuse of names today.
- The values are under the rules of `pin`, stable since 2026-11-19
  (`TODO-pin.md`, section "Stable"): a loaded value is unpinned, and a
  table used twice as the same object would be a shared node.

## 4. Open, for the author to decide

- Two uses of a name: `X` alone inserts the table as a value (a
  positional entry, or the value of a field), and `X...` spreads its
  entries into the enclosing constructor.
- Whether the spread exists only in the loader, or also in the
  language (`[t...]` in a program).
- Conflict of fields between the constructor and what is spread
  (suggestion of `pico-slides`: the later one wins, replacing the whole
  field, with no deep merge). For the style groups of `pico-slides`
  (`font=[size=]` over `font=[file=]`) a shallow replace loses the
  other field: whether a deep merge is wanted is part of this.
- Positional entries of a spread table: appended as positionals, or
  the spread restricted to named fields.
- No expressions: only names and spread, no operations and no calls,
  so that the text is still data.
- Copy or sharing: a name used twice should give two equal tables, so
  that the result is a tree with no shared nodes and `X.dump` of it
  works.
- A name that refers to an earlier name (`B = [A..., x=1]`): allowed in
  order of definition, with no recursion.
- Round trip: `X.dump` cannot recover the names, so a text read with
  `loadx` is written back expanded.
- Errors: an undefined name, a name defined twice, a definition after
  the value, each with the line.
- The syntax of a definition (`ID = Value`, with or without a keyword
  such as `val`), and what marks the final value.
- One function or two: a new `X.loadx`, or `X.load` extended (see
  section 3: no text that loads today would change).
- Names given from the program: `X.loadx(s, [TITLE=...])`, so that a
  theme is defined in the program and used by the document.
