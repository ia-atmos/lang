# atmos-tag: a more primitive form of the tag of a table

Material for the session `atmos-tag`, where the author discusses whether
the tag of a table should stop being a plain key. Gathered on 2026-11-22
by the session that maintains the compiler (`atmos-lang`), from what
`atmos-iter` sent with the request. It has the request (section 1),
what exists today (2), how the ports use it (3), and questions (4).
Nothing in section 4 is decided.

## 2. What exists today

On `main` at `f416c03` and after. Manual: "Hierarchical Tags",
"Equivalence".

- A tag is a string at run time: `:x == 'x'` ("Tags are syntactic
  values that only exist at compile time").
- A tagged table is a table with the plain key `"tag"`:
  `:Pos [x=10,y=20]` is `[tag=:Pos,x=10,y=20]`. `t.tag` reads it,
  `set t.tag = :Q` writes it, `t@("tag")` is the same key.
- `??` over a table reads that key and compares prefixes of the
  hierarchy (`:T.A.x ?? :T.A`).
- The runtime builds the key with `a_strz("tag")` in six places:

| Where | What |
|---|---|
| `rt/tab.c` `a_tag` | the constructor `:T [...]` sets the key |
| `rt/ops.c` | `??` reads it |
| `rt/std.c` | a function that collects the entries "except the tag" (around line 381) |
| `rt/lload.c` (twice) | `X.load` and `X.dump`: the reader sets it, the writer prints `:T [...]` |
| `rt/task.c` `toggle_evt` | the event `:T [b]` of a `mute on :T` |

- On the branch `iter` (d1bbd88, not merged), decided as
  `atmos-iter#14a`: `loop` and the functions of `iter` skip the key
  `tag` in `a_next`; `t.tag`, `??`, `++` and `X` still see it. Before
  it, `:T [10, 20]` walked `0 1 tag`.
- Related in `atmos-iter`: `#12` and `#13` (vector and dictionary as
  kinds of a table, how the kind is known, its names for `type`, `??`
  and `match`), open there.

## 4. Questions

- **Where the tag lives.** A key as today (with the skip of `#14a`),
  or a field in the header of the table, out of the keys, as the `pub`
  of a task. In the header it is never a key (the list of `atmos-iter`): `loop`, `#`, `++`,
  `X.copy` and the walk do not see it, and `??` and `match` read it
  directly.
- **How a program reaches it.** `t.tag` kept as the spelling (then
  `t.tag` and `t@("tag")` differ), a new form (`tag(t)`, an operator),
  or both. Whether `set t.tag = :Q` stays, and whether a tag can be
  removed.
- **The constructor.** `:T [...]` unchanged. What `[tag=:T, x=1]`
  becomes: a plain key named `tag` (the ports write about 21 of them),
  or still the tag.
- **What a tag is at run time.** A string today (`:x == 'x'`). A more
  primitive tag could also be its own type (interned, compared by
  identity), which changes `type`, `tostring`, `==` with strings and
  the keys of tables written as `:x`.
- **Vector and dictionary.** If `atmos-iter#12` makes kinds of a table,
  a tag in the header lets a tagged vector stay a vector.
- **Data.** `X.load` and `X.dump` write `:T [...]` already; what they
  do with a key `tag` written as a field.
- **The branch `iter`.** If the header form is chosen, the skip of
  `#14a` in `a_next` is not needed; `atmos-iter` drops it from its
  branch when told.
- **The reference.** `atmos-lang/atmos` (Lua) keeps the tag as a key,
  as far as the golden tests show; the header departs from it.
- **The cost.** A field in the header of every table (8 or 16 bytes),
  against a lookup of the string `"tag"` in the hash part for each `??`
  and `match`.
