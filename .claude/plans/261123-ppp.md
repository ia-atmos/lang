# atmos-ppp: the tip markers `@#` and `@+`

Material for the session `atmos-ppp`, where the author discusses the
shortcuts `t@#` and `t@+` (`ppp` is the name of their tests in the
reference) and whether `+=` should work on vectors.
Gathered on 2026-11-23 by the session that maintains the compiler
(`atmos-lang`). It has the request (section 1), what exists today (2),
how the ports use it (3), and questions (4). Nothing in section 4 is
decided.

## 1. The request

**Autor** (2026-11-23, in `atmos-lang`):
> about @+ shortcuts, open a new session atmos-ppp. i wonder if they are
> still relevant. should we extend += for vectors?

## 2. What exists today

On `main` (2026-11-23). Manual, "Indexing" and "Set".

```
Expr : Expr `@´ (`#´ | `+´)     ;; t@#  t@+
```

- `t@#` is the last index (`#t-1`), `t@+` the append index (`#t`); the
  first index of a vector is 0. They work wherever an index does:
  read, `set`, table constructors, spawn pools, emit targets.
- Reading `v@+` gives `nil`. `set v@# = nil` removes the last element
  (a pop). There is no marker for pop as an expression that gives the
  value.
- The reference (`atmos-lang/atmos`, Lua) has the same two markers,
  with indexes from 1 (`#t` and `#t+1`). Its tests `ppp-1` to `ppp-6`
  are in `tst/golden` (0058 to 0063), rewritten here for indexes from 0.
- Compound assignment: `set x OP= e` is `set x = x OP (e)`, evaluating
  the location once, for `+ - * / // % ++ & | ^ << >> && ||`
  (manual, "Set"). It needs a mutable location: a `var` or an index.
- `++` on two tables makes a NEW table with the entries of both
  (vectors in sequence). So `set w ++= [9]` builds a new vector and
  rebinds `w`; it works on a `var` and on a field (`set g.xs ++= [2]`),
  not on a `pin` (`invalid set : expected mutable variable`), and it
  copies the whole vector at each use.
- `set w += 4` on a vector is a run-time error (`invalid operation '+'
  : expected number : got table`).
- The library: `vector.insert(t, v)` appends and gives `v`;
  `vector.insert(t, i, v)`; `vector.remove(t [, i])` removes and gives
  the element (the last by default); `vector.clear`.

Checked on main:

```
pin v = [1, 2]
set v@+ = 3          ;; [1, 2, 3]
print(v@#, #v)       ;; 3   3
set v@# = nil        ;; [1, 2]
var w = [1]
set w ++= [9]        ;; [1, 9], a new table
set w += 4           ;; error: expected number
```

## 3. How the ports use it

Counted on 2026-11-23 over the `.atm` files of the clones of the ports
and environments, comments not excluded; approximate.

| Form | Count |
|---|---|
| `set t@+ = v` (append) | 359 (pico-1oom 147, sdl-flare 90, sdl-snxkx 65, ray-lessmilk 31, pico-slides 14, env-pico 6, sdl-tux 4, env-uv 2) |
| reading `t@+` | 0 |
| `t@#` | 7 |
| `vector.insert(` | 74 (appends and inserts at an index together) |
| `++=` | 0 |
| `set x = x ++ [...]` | 0 |

So `@+` is the common way to append (about five times
`vector.insert`), `@#` is rare, and no port appends by `++`.

## 4. Questions

- **Keep, change or drop the markers.** `@+` is used 359 times; `@#`
  7 times; reading `@+` never. Options: keep both; keep `@+` only
  (`@#` becomes `t@(#t-1)`); replace them with another form.
- **`+=` on vectors.** `set v += x` as an append in place (the vector
  stays the same table, so it works on a `pin`). Questions: what if
  `x` is itself a vector (append it as one element, or its elements);
  whether `-=` removes; how it reads beside `+=` on numbers (a run-time
  dispatch on the type of the location); and `++=`, which today copies.
- **`++=` in place.** Make `set v ++= w` append the elements of `w` to
  `v` in place instead of building a new table, so that it works on a
  `pin` and costs no copy (it changes what `++=` means for a `var`
  that someone else also refers to).
- **Pop and peek as values.** `vector.remove(t)` gives the last; a
  marker could too, or not.
- **The `pin` rules.** An append stores a value into a pinned vector:
  the ceiling and `set :out` (`set :out out@+ = o` is in the manual)
  apply as for any index; whatever form is chosen must keep that.
- **Interplay.** `atmos-iter` (functions over iterables, the kinds of a
  table: `#12`, `#13` there), `atmos-slices` (views of vectors), and
  `atmos-tag` (the tag in the header, done) touch the same values.
