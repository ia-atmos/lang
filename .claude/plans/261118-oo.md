# atmos-oo: functions of the same name dispatched by tag

Material for the session `atmos-oo`, where the author discusses whether
and how Atmos declares and dispatches functions of the same name by the
tag of a value. Gathered on 2026-11-18 by the session that maintains
the compiler (`atmos-lang`). It has the conversation that led here
(section 1), what the language offers today (2), a suggestion (3), and
the questions (4). Nothing in section 3 is decided.

**Autor:**
> I think wo meta tables this pattern is gone? Discuss

**atmos-lang:** yes, mostly. This implementation has no metatables. In
Lua, `o:f(x)` is `o.f(o, x)` and `o.f` is found through `__index` in a
table shared by all objects of a class: that sharing is the pattern.
Here `o::f(x)` could only find `f` stored in `o` itself. Tried:

| Style | Result |
|---|---|
| Method stored in each object: `[v=1, inc=func (self) {...}]`, `a::inc()` | works; every object carries every function |
| Shared table of methods: `Counter.inc`, then `b::inc()` | `expected function : got nil`: nothing links `b` to `Counter` |
| Through the module: `Counter.inc(b)` | works; what all ports write |
| Closure: `[inc = \{ set v = v + 1 ; v }]`, `c.inc()` | works with a plain dot and no `self` |

What still gives polymorphism: a record of functions
(`atmos.env([step=..., quit=...])` is an interface with one
implementation per environment), tasks, and tags with `match`. What is
lost: open dispatch (with `match`, a new kind means editing every
function that matches on it), inheritance of behavior, operator
overloading. Idea left on the table: dispatch on the tag, which every
tagged table already carries and which is hierarchical.

## 2. What the language has today

- A tag is a value (`:Enemy.Boss`), hierarchical by its dots: `:T.A.x
  ?? :T` is true. A tagged table `:Pos [x=10]` is `[tag=:Pos, x=10]`;
  `t ?? :T` tests it; `match` and `ifs` choose by it. The tag is an
  ordinary field (`t.tag`).
- `func f (...) {...}` declares a name; a second `func f` assigns the
  name again (the first is lost). `func m.f` declares a field.
- A parameter takes a modifier (`var x`, `pin x`); nothing else.
- Calls are being redefined by the session `atmos-args` (`f x, y`).

## 3. A suggestion

### 3.1 The form: a tag on the first parameter

```
func draw (s :Shape)        { print("shape") }
func draw (c :Shape.Circle) { print("circle", c.r) }

func area (c :Shape.Circle) { 3 * c.r * c.r }
func area (r :Shape.Rect)   { r.w * r.h }

val xs = [:Shape.Circle [r=1], :Shape.Rect [w=2, h=3]]
loop _, x in xs {
    draw(x)                 ;; circle 1 ; shape
    print(area(x))          ;; 3 ; 6
}
area(:Shape.Line [])        ;; error: no 'area' for :Shape.Line
```

- **Declaration**: a parameter followed by a tag. Each such `func` adds a
  *clause* to the function of that name, instead of replacing it.
- **Call**: an ordinary call, `draw(x)`. No new call syntax, no `self`,
  nothing stored in the value: the function chooses its clause by the
  tag of the argument.
- **Resolution**: the clause of the most specific tag that the value
  has, up the hierarchy (`:Shape.Circle`, then `:Shape`), then a
  clause with no tag, if there is one (the default); else an error that
  names the function and the tag.
- **Open**: a new kind adds its clauses where it is declared, in its own
  file, with no edit to the others. That is what `match` cannot do.

It is the generic function of CLOS, Dylan, Julia, and Clojure's
multimethods and protocols, restricted to one argument and to tags.

### 3.2 It runs today as a library

No change to the compiler: a table from tags to functions and a walk up
the tag. Tested with the compiler at `b4424ff` (prints `circle 1`, `3`,
`shape`, `6`, and catches the missing clause):

```
;; a library prototype of dispatch by tag, with no change to the language
func generic (name) {
    val ms = []                         ;; tag -> function
    val call = func (o, ...) {
        var tag = tostring(o.tag)       ;; "Shape.Circle"
        loop {
            val f = ms@(tag)
            if f { return f(o, ...) }
            var i = #tag - 1            ;; the last dot: the parent tag
            loop {
                until (i < 0) || (string.sub(tag, i, i) == ".")
                set i = i - 1
            }
            until i < 0
            set tag = string.sub(tag, 0, i - 1)
        }
        throw(:Dispatch [name=name, tag=o.tag])
    }
    [call=call, ms=ms]
}

val draw = generic("draw")
set draw.ms@("Shape")        = func (s) { print("shape") }
set draw.ms@("Shape.Circle") = func (c) { print("circle", c.r) }
val area = generic("area")
set area.ms@("Shape.Circle") = func (c) { 3 * c.r * c.r }
set area.ms@("Shape.Rect")   = func (r) { r.w * r.h }

val xs = [:Shape.Circle [r=1], :Shape.Rect [w=2, h=3]]
loop _, x in xs {
    draw.call(x)
    print(area.call(x))
}
print(catch :Dispatch { area.call(:Shape.Line []) })
```

So the syntax of 3.1 would be sugar over this, with the lookup in C (a
table per function indexed by the tag, with the walk cached).

### 3.3 Other forms considered

| Form | Example | Note |
|---|---|---|
| A tag on the parameter (3.1) | `func area (c :Shape.Circle)` | recommended: the call does not change |
| The tag before the name | `func :Shape.Circle.area (c)` | ambiguous: `:Shape.Circle.area` is itself a tag |
| A table of methods per tag, and a method call | `methods :Shape.Circle [area = ...]` ; `c::area()` | brings back a call syntax and a hidden link from the value |
| Only the library (3.2) | `area.call(x)`, `set area.ms@(...) = ...` | no syntax; the clauses are assignments, not declarations |
| Nothing | `match` in each function | closed: what the ports do today |

## 4. Questions for the author

One at a time, each with a recommendation after the session measures.

- **Is there a real case?** No port asked for it. Look in the ports for
  `match`/`ifs` over the tag of an entity repeated in several
  functions (the powers and enemies of Flare, the characters of SNKRX,
  the actions of Pingus, the badguys of SuperTux): each is a candidate,
  rewritten both ways, before any syntax is chosen.
- **One argument or several?** Dispatch on the first only (simple, a
  table per function) or on all tagged parameters (multimethods: a
  collision between two kinds, `hit(a :Ship, b :Rock)`).
- **The parent clause**: how a clause calls the one above it (the
  `super` of classes): a form such as `draw(s :Shape)` at the call, a
  function `next()`, or nothing.
- **Values with no tag**: numbers, strings, tasks. A default clause only,
  or the type as a tag (`:number`, `:task`)?
- **Tasks**: `task T (e :Enemy.Boss)` as clauses of a task prototype, so
  that `spawn Enemy(e)` picks the body by the kind?
- **Where clauses may be declared**: today a second `func f` replaces the
  first. With a tag it adds; a clause for the same tag twice is an
  error or a replacement? Clauses inside blocks (local functions)?
- **Cost**: one lookup per call of a generic function, by the tag
  (cached); none for ordinary functions.
- **With the other sessions**: `atmos-args` is changing how calls and
  parameters parse (`f x, y`; a tag after a parameter must not read as
  an argument); `atmos-pin` owns the rules of the prototypes as names.
