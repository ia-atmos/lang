# atmos-blocks: the event of termination of a transparent block

Material for the session `atmos-blocks`, where the author discusses
item `atmos-lang#6`: whether a transparent block (`spawn { ... }`, a
branch of a `par`, the block of a `toggle on`) should emit an event
when it ends. Gathered on 2026-11-20 by the session that maintains the
compiler (`atmos-lang`). It has the request (section 1), what happens
today (2), the attempt to remove it (3), and the questions (4). Nothing
in section 4 is decided.

## 1. The request

Item 6 of the compiler's list since the start: "The event of
termination of transparent blocks. Remove it. It changes the semantics,
and two golden tests must be adapted" (the recommendation was
`atmos-lang`'s; the author never answered it).

## 2. What happens today

A task that terminates is an event: `await t` and `await :xtask` see it,
and its value is `t.ret`. A transparent block has no identity (it shares
the slots of its task and has no `pub`), but when it ends normally the
runtime makes up a terminated task for the occasion, with the value of
the block as its `ret`, and emits it to the subtree of the task
(`trail_emit` in `rt/task.c`, called from `trail_end`). A block that is
aborted emits nothing.

Run on `main` (`ae69518`):

```
spawn {
    await :x
    print("block A ends")
    42
}
spawn {
    val e = await true          ;; any event
    print("B woke with", e, e ?? :xtask)
}
spawn {
    val e = await :xtask        ;; the end of any task
    print("C woke with", e)
}
emit :x
print("main goes on")
```

```
block A ends
B woke with     xtask: 0x...    true
C woke with     xtask: 0x...
main goes on
```

So the end of block A awakes two siblings that named nothing of A: one
awaiting any event, one awaiting the end of any task. The value they get
is a task that nobody spawned, whose `ret` is 42. A golden test reads it
so: `(func (it) { print(it.ret) }) (await(true))` prints 10 for a
sibling block that ends with 10 (`golden/0416-return-2`).

The same event is how the runtime itself waits for blocks: `par :all`
and `par :any` await the trails of their branches (`a_await_trails`,
`PK_TRAILS`), and a branch that ends awakes the `par` through this emit.

The reference implementation (`atmos-lang/atmos`, in Lua) does the same
as far as the golden tests show; they came from it.

## 3. The attempt to remove it (2026-11-20)

Under the rule of work with no input, `atmos-lang` tried the plain
removal on a branch: in `trail_end`, a block that ends normally drops
its value and emits nothing. Seven cases fail, so it was undone and
nothing is prepared:

| Case | What it has |
|---|---|
| `cases/par-04`, `cases/par-09`, `cases/trail-04` | `par :all` with values, nested, with tasks awaited in the branches |
| `golden/0453-par-all-1`, `golden/0459-par-all-3-return` | `par :all` |
| `cases/toggle-05` | a `par` inside a `toggle on` |
| `golden/0416-return-2` | a block that reads the `ret` of a sibling block by `await(true)`: the one case that observes the event from a program |

Six of the seven fail because the `par` is never awoken: the wait of a
`par` rides on the event. Only `0416-return-2` is a program that depends
on the event as part of the language. The old note said "two golden
tests must be adapted"; the second one was not identified in this
attempt.

So the removal has two parts that are separate: the wait of a `par` for
its branches needs its own wake-up (a direct resume of the waiting
trail when a branch ends, with no emit), and then the event can go.

## 4. Questions

- **Should the event exist?** A block has no identity, and a program
  cannot name it; yet its end is visible to anything that awaits `true`
  or `:xtask`, with a task that nobody spawned as the payload. Options:
  remove it (a block ends in silence; only what awaits it by structure,
  a `par` or the block that encloses it, goes on); keep it as it is; or
  keep it only for who can name the block (`pin b = spawn { ... }`
  promotes the block to a task, which is an event already).
- **The cost.** Each end of a block is a broadcast to the subtree of its
  task. `doom` measured about 180 instructions per emit for each task
  that awaits another event (`atmos-lang#96`): a game with many short
  blocks pays it at each end. A direct wake-up of the `par` would not.
- **What changes for programs.** An `await true` no longer wakes when a
  sibling block ends. A first count on the 15 clones of the ports
  (2026-11-20): no `.atm` file has an `await true` / `await(true)` nor
  an `await :xtask`. So no port observes the event by those forms; an
  await with a predicate over any event (`await \{...}`) was not
  counted, and the suites of the ports are the real test.
- **The value of a block.** `val x = par :all {...}` and `val v = spawn
  {...}` (a promoted block) get the values by structure; nothing there
  needs the event. To confirm in the implementation.
- **The reference.** Removing it departs from `atmos-lang/atmos`, as
  `atmos-lang#60` (where the exception of `emit @t` goes) does.
- **Related, in other sessions.** `atmos-pool` (order of awaking, the
  emits in `rt/task.c`), `atmos-grab` and `atmos-context` (both hook the
  resume of a trail on their branches). Three branches wait to merge in
  the same file: a change here should come after them or be told to
  them.
