environments of this implementation. Gathered on 2026-11-17 by the
session that maintains the compiler (`atmos-lang`), at the author's
request: everything on environments said in that session, and the
decisions and open items that came out of it.

How to read it:

- Section 1 is the conversation itself. A past conversation cannot be
  moved into a new session as turns, so each turn is a quote with its
  speaker: **Autor:** for the author's words, verbatim (his messages are
  in Portuguese or English), and **ceu-atmos:** for the answers of the
  compiler session, verbatim. Status lines in between were dropped.
  The conversation of 2026-11-09 to 2026-11-12 is not in the local
  record of that session, and is not here.
- Section 2 is the state of the environments today.
- Section 3 is what is open, with the numbers of the list of the
  compiler session (`.claude/plans/TODO.md`), which do not change.
- Section 4 lists the plans and documents to read.

**ceu-atmos:**

> **Rede mais portável: libuv.** É a que tem suporte de primeira linha nos três sistemas (epoll no Linux, kqueue no Mac, IOCP no Windows) e já entrega TCP, UDP, DNS, timers, arquivos e processos num modelo de eventos, que casa direto com `await`.
>
> | Opção | Portabilidade | Para quê | Ressalva |
> |---|---|---|---|
> | **libuv** | Linux, Mac e Windows nativos | Rede geral, arquivos, timers | É dona do laço principal; precisa conviver com o laço da GUI |
> | Sockets BSD + `select` | Boa, com `#ifdef` para Winsock | TCP e UDP simples, sem dependência | É o que o luasocket faz por baixo |
> | ENet | Boa | UDP confiável para jogos | Só isso |
> | SDL_net | Boa | Só se já estiver em SDL | Limitada, sem DNS assíncrono |
>
> **Atenção ao IUP no Mac:** pelo que sei, o IUP é nativo no Windows e usa GTK no Linux, mas no Mac só roda via GTK/X11. O driver Cocoa nunca foi concluído oficialmente. Não consegui confirmar isso agora (a rede desta sessão é restrita). Se o Mac importa, o elo fraco é o IUP, não a rede.

>

>
> A libuv binding: timers, TCP client and server, DNS, files. UDP and processes later.

>

I would let `env-uv` own the loop but also expose a single-step function, so a GUI environment can drive it later. The alternative is to design the composition now, together with `env-iup`.

>

> - **Mac:** no native driver, as far as I know (unverified).

> **The question:** what to build on it. I suggest the 7GUIs tasks (counter, temperature converter, flight booker, timer, CRUD, circle drawer, cells). It is a known GUI benchmark and gives the paper a non-game data point.

> The `uv` session already finished its first milestone and found a real compiler defect. I fixed it, and it is in `main` (`d615e1b`) with the suite passing: 317 cases, 444 golden.
>
> **The defect:** a value returned by an awaited task could not be pinned.
>
> ```
> pin a = f()             ;; fine
> pin b = await T()       ;; ERROR: invalid pin : shared value
> ```
>
> A `pin` requires the value to have no other reference. But when `await T()` returned, the finished task still held its result, and the task itself was still alive as the event announcing its own termination. So the value always had two references.
>
> **Why it mattered:** in a libuv binding every operation that waits is a task, and each returns a connection handle. The form my plan itself prescribed, `pin s = await uv.tcp.accept(srv)`, could never work. The session had fallen back to plain `val`.
>
> **The fix:** a task that the `await` itself spawns now hands its result over, the way a function call does. `pin s = await T()` works, for native values too.
>
> **This is a semantic choice I made, so it needs your eye.** It has two consequences:
>
> - The task that comes back as the second result no longer holds the value. After `val v, t = await T()`, `t.ret` is `nil`.
> - A task awaited by reference (`await(t)`, with `t` spawned earlier) is unchanged: it keeps its result, anyone awaiting it shares it, and it still cannot be pinned.
>
> The alternative I considered was narrower: move the result out only when the source code literally says `pin x = await T()`. I rejected it because the behaviour would then depend on syntax around the `await`, and no existing test relied on the old behaviour. I recorded the choice in the TODO under "decided, not acknowledged" and in the manual. Say so if you prefer the narrow version.
